# 03: SO-101 (the camera arm)

**Done when:** `look` and `stow` are saved, and going to `look` 10 times puts a fixed AprilTag within about 3 px of the same spot every time.

## Tasks

- [ ] Mount the USB camera on the SO-101 gripper or wrist, rigidly (hot glue, zip ties, or a printed bracket). If the camera wobbles, calibration is worthless.
- [ ] Route the camera cable along the arm with some slack at every joint.
- [ ] Teach the poses. `save` turns torque off, so **hold the arm** while you do it:
  ```sh
  python so101.py save look    # camera over the bin, looking as straight down as it can
  python so101.py save stow    # folded away, clear of the RoArm's whole path
  ```
  (`drive` is only needed for route driving; skip it for now.)
- [ ] **The `look` pose:** the whole bin floor should be in frame with a small margin. Point the camera as close to straight down as you can: the more top-down it is, the smaller the parallax error on tall items (step 06).
- [ ] **Repeatability test:** tape one AprilTag (any id from `AprilTags/`, not `calib_tag`) inside the bin. Then 10 times: `python so101.py go stow`, `python so101.py go look`, `python vision.py photo`, and note the tag's pixel position. If it spreads more than about 5 px:
  - approach `look` from the same direction every time (always come from `stow`);
  - lower the SO-101 `speed` in `so101.py` if it overshoots.
- [ ] Check that the RoArm at `park` is not in the `look` frame, and that the SO-101 at `stow` is not in the RoArm's path.

## Pitfalls

- SO-101 servos stop a few degrees short under load (low P gain). `move()` accepts up to 10° short as "arrived", but it's the repeatability that matters, not the absolute accuracy.
- Keep the SO-101 torque on during `sort`. If it drops out, `look` isn't the same pose any more.
